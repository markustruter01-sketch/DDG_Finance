---
name: Client order ID uniqueness
description: Every Alpaca order submission must use a bounded per-call UUID client-order ID with one duplicate-ID retry.
---

Client order IDs must be generated by the shared bounded UUID helper and begin with the environment component `pub`, `dev`, or fail-closed `unk`; prefixes may preserve ownership context, but date, symbol, queue, or bot text cannot provide uniqueness.

**Why:** Alpaca retains canceled IDs, so fixed and same-day IDs collide on repeated protective-stop or operational retries.

**How to apply:** Route every broker submission through the shared generator and retry exactly once only when Alpaca reports a duplicate client-order-ID rejection. Ownership matching must understand tagged IDs while retaining legacy untagged orders for safe stop reconciliation.
